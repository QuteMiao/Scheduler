总览 Overview

这个项目是一个面向昇腾 NPU 的任务级 DAG 调度器：给定一张静态的、带依赖关系的计算图，调度器负责把「当前可执行」的任务源源不断地派发到计算单元，并在任务完成后解锁其后继任务，直到整张图执行完毕。

一句话概括运行逻辑：Painter 线程负责「拆依赖、产出就绪任务」；Dispatch 线程负责「把就绪任务派发到空闲核、回收完成状态」；两类线程通过两张环形队列（就绪队列 / 完成队列）解耦、形成一个闭环的流水线。

架构与数据流 Architecture & Data Flow

整个调度器是一个生产者-消费者流水线：Painter 是「就绪任务」的生产者，Dispatch 是消费者；反过来 Dispatch 又是「完成事件」的生产者，Painter 是消费者。两个方向分别用一张环形队列承载。

一次完整循环（闭合回路）pipeline

  1. 初始化：main() 调 init_queue()，把所有前驱数为 0 的任务放入就绪队列。
  2. 派发：Dispatch 线程从就绪队列批量取出任务，按空闲核位图逐个塞进空闲核（占用 free_bitmap）。
  3. 执行/完成：模拟模式下，任务派发的同时就置位 msg_bitmap（表示「已完成」）；真机上则等硬件回写寄存器。
  4. 回收：Dispatch 线程读回 msg_bitmap，把完成任务的 id 写入完成队列。
  5. 解析：Painter 线程从完成队列取任务，把每个后继的 total_pre_cnt 减一；减到 0 则入就绪队列。
  6. 终态：当累计完成数 = 总任务数时，Painter 0 号置位 g_is_done，全部线程退出。
解耦的关键：两类线程不直接通信，只通过就绪队列（Dispatch 消费）与完成队列（Painter 消费）交换 task_id。这使 Painter 的「图遍历」与 Dispatch 的「硬件派发」可以按不同线程数独立伸缩（PAINTER_THREAD_CNT vs DISPATCH_THREAD_CNT）。

启动时序 startup

int main(void) {
    init_ctrl_t();          // 初始化就绪/完成队列 + 每 dispatch 线程的位图控制块
    init_queue();     // 无前驱任务 → 就绪队列
    signal(SIGINT,  handle_signal);   // Ctrl+C 优雅退出 → 置 g_is_done
    signal(SIGTERM, handle_signal);
    // 1) 创建 PAINTER_THREAD_CNT 个 painter 线程（Linux 下绑核 3+i）
    // 2) 创建 DISPATCH_THREAD_CNT 个 dispatch 线程（Linux 下绑核 2）
    // 3) 先 join 所有 painter，再 join 所有 dispatch
}
「先 join painter、再 join dispatch」的顺序很关键：完成标志由 painter 置位，dispatch 线程依赖该标志退出；若反了顺序可能导致 dispatch 空转等待。

线程运行逻辑 Thread Logic

程序一共有 1 + PAINTER_THREAD_CNT + DISPATCH_THREAD_CNT 个线程。三类线程用 g_start_barrier 原子计数器做「起跑同步」，用 g_is_done 原子布尔做「收工同步」。

① 启动屏障 g_start_barrier

每个 worker 进入循环前执行 atomic_fetch_add(&g_start_barrier.v, 1) 拿到自己的序号 cnt，然后自旋直到 cnt >= (DISPATCH + PAINTER)，保证所有线程都就绪后才同时开始调度，避免先跑的线程空转抢锁。

int cnt = atomic_fetch_add(&g_start_barrier.v, 1);
while (cnt < (DISPATCH_THREAD_CNT + PAINTER_THREAD_CNT))
    cnt = atomic_load(&g_start_barrier.v);

② Painter 线程 painter()

Painter 是「图的消费者 + 就绪任务的生产者」。每个 painter 拥有一个独立的完成队列读游标，只处理自己那部分的完成事件。

void *painter(void *arg) {
    int tid = (int)(intptr_t)arg;
    /* ... 启动屏障 ... */
    uint64_t start_ns = get_time_ns();
    bool is_done = false;
    while (!is_done) {
        deal_completed_queue(tid);   // 核心：消费完成事件 → 解析依赖 → 入就绪队列
        is_done = atomic_load(&g_is_done.v);
    }
    if (tid == 0)  // 0 号 painter 统计吞吐
        printf("scheduler_throughput,%.2f,MTasks/s\n",
               (float)(total_task_cnt * 1000.0 / elapsed_ns));
}
deal_completed_queue(tid) 展开
void deal_completed_queue(int tid) {
    // 零拷贝：直接拿到指向环形缓冲当前游标处的一批 task_id（不复制）
    const uint32_t *cq = completed_queue_read_batch(&g_completed_queue, tid, &cnt, CQ_BATCH_SIZE);
    if (cnt <= 0) return;

    if (tid == 0) {              // 只有 0 号 painter 累计完成数
        completed_task_cnt += cnt;
        if (completed_task_cnt >= total_task_cnt)  // 全图完成 → 广播退出
            atomic_store(&g_is_done.v, true);
    }
    resolve_dep(tid, cnt, cq, rq_buf, ready_cnt);  // 遍历后继、递减前驱数、产出就绪
    completed_queue_read_commit(&g_completed_queue, tid, cnt);  // 推进读游标
    send_2_ready_queue(ready_cnt, rq_buf);      // 就绪任务批量入队
}

③ Dispatch 线程 dispatch_worker()

Dispatch 是「就绪任务的消费者 + 完成事件的生产者」。真机上先与硬件握手，模拟模式下这段基本是空操作。

void *dispatch_worker(void *arg) {
    int tid = (int)(intptr_t)arg;
    for (i...) { hand_shake(tid, spr1[i], i, 0);  // 真机握手，模拟下为空
                 hand_shake(tid, spr2[i], i, 64); }
    /* ... 启动屏障 ... */
    bool is_done = false;
    while (!is_done) {
        dispatch(tid);                  // 一轮：回收完成 → 派发就绪
        is_done = atomic_load(&g_is_done.v);
    }
}

dispatch(tid) 的三大步 dispatch()

int dispatch(int tid) {
    read_msgq(tid);                 // ① 把 msg_bitmap 合并进 free_bitmap（完成核被释放）
    push_2_completed_queue(tid);   // ② 扫 msg_bitmap 取出完成 task_id → 写入完成队列
    send_task(&g_ctrl_t[tid], TASK_TYPE_MIX);     // ③ 依次派发 MIX/VECTOR/CUBE
    send_task(&g_ctrl_t[tid], TASK_TYPE_VECTOR);
    send_task(&g_ctrl_t[tid], TASK_TYPE_CUBE);
}
模拟 vs 真机的分界点在 #ifdef REAL_CHIP：模拟（默认）下 send_task 派发时立即置位 msg_bitmap（任务瞬间「完成」），因此下一轮 read_msgq 就能回收；真机则通过读写 AICORE 寄存器（aicore_spr、READ_REG/WRITE_REG）与硬件交互。

数据结构 Data Structures

调度器的高性能来自两个设计：① 环形队列把「生产/消费」两侧的锁拆开；② 热共享原子按缓存行（64B）对齐以避免伪共享（false sharing）。

就绪队列 queue_t · MPSC

g_ready_queue[TASK_TYPE_CNT]（每个任务类型一个）。生产者（Painter）只碰 tail+tail_lock，消费者（Dispatch）只碰 head+head_lock，两侧互不阻塞。head/tail 是单调递增的 64 位计数，下标永远是 counter & (RQ_SIZE-1)。

typedef struct queue {
    /* consumer-owned */
    _Alignas(64) _Atomic uint64_t head;
    _Alignas(64) atomic_flag head_lock;
    /* producer-owned */
    _Alignas(64) _Atomic uint64_t tail;
    _Alignas(64) atomic_flag tail_lock;
    uint32_t tasks[RQ_SIZE];   // RQ_SIZE=4096
} queue_t;
批量出入队 batch_enqueue / batch_dequeue 都支持跨环形尾部回卷（分两次 memcpy），并处理「满/空」快路径。锁是 atomic_flag 自旋锁（test_and_set + seq_cst fence）。

完成队列 completed_queue_t · MPMC

多个 Dispatch 线程写、多个 Painter 线程读。单一写者锁 write_lock 串行化写入；每个 Painter 有独立的读游标 read_pos[painter_tid]。一条记录只有所有 Painter 都读过后才允许被覆盖。

typedef struct {
    uint32_t ring[CQ_SIZE];                 // CQ_SIZE=4096
    cacheline_u64_t write_pos;                // dispatcher 写
    cacheline_u64_t read_pos[PAINTER_THREAD_CNT];  // 每 painter 一行
    cacheline_flag_t write_lock;              // 串行化写者
} completed_queue_t;
零拷贝读：completed_queue_read_batch 直接返回指向 ring 的指针（不复制），并 clamp 到环形物理边界保证连续；消费完再 read_commit 推进游标。

Dispatch 控制块 ctrl_t

每个 Dispatch 线程一个 g_ctrl_t[tid]，描述它「拥有」哪些核、哪些核空闲、哪些任务在跑。

typedef struct ctrl {
    uint64_t free_bitmap[TASK_TYPE_CNT][2];  // bit=1 → 该核/slot 空闲（每核 2 个 slot）
    uint64_t msg_bitmap[EXE_TYPE_CNT][2];   // bit=1 → 任务已完成（模拟下派发即置位）
    uint64_t aicore_mask;                    // 本线程拥有的核掩码（默认 60 个核）
    uint32_t task_id_map1[EXE_TYPE_CNT][64]; // 核/slot → 正在执行的 task_id
    uint32_t task_id_map2[EXE_TYPE_CNT][64];
    uint64_t* aicore_spr_1/2[EXE_TYPE_CNT][64]; // 真机寄存器地址
    uint32_t tid;
} ctrl_t;
「每核 2 slot」：AIC_OSTD=2 意味着每个 AI 核可同时驻留 2 个任务（slot 0 / slot 1）。send_task 优先用 slot 0，忙则用 slot 1，用 free_bitmap[type][slot] 记录占用。

核心算法 Core Algorithms

四个关键函数串起整个调度：初始入队、依赖解析、位图派发、完成回收。核心思想是「前驱计数递减 + 位图状态机 + 批量操作」。

① 初始入队 init_queue()

扫描全局任务表，把所有「入度 = 0」的任务按类型放入对应就绪队列。

for (i...) {
    task_id = total_task_id[i];
    if (test_graph[0].total_pre_cnt[task_id] <= 0) {   // 无前驱
        type = total_type[task_id];
        idx  = atomic_fetch_add(&g_ready_queue[type].tail, 1);
        g_ready_queue[type].tasks[idx] = task_id;
    }
}

② 依赖解析 resolve_dep()

对每个完成的任务，遍历它的后继（successors[]），把后继的 total_pre_cnt 减一；一旦归零，该后继就「就绪」，收集到 rq_buf 待批量入队。

void resolve_dep(tid, cnt, cq_buf, rq_buf, ready_cnt) {
    for (j < cnt) {
        task_id = cq_buf[j];                     // 一个已完成任务
        succ_cnt = test_graph[tid].suc_cnt[task_id];
        idx = test_graph[tid].suc_idx[task_id];  // 后继在 successors[] 的起始下标
        for (k = idx; k < idx + succ_cnt; k++) {
            succ_id = test_graph[tid].successors[k];
            test_graph[tid].total_pre_cnt[succ_id]--;   // 前驱数 -1
            if (total_pre_cnt[succ_id] < 1) {          // 全部前驱已完成
                rq_buf[type][ready_cnt[type]++] = succ_id; // 就绪，待入队
            }
        }
    }
}
图的存储用 CSR（压缩行）风格：suc_idx[task] 记录起始偏移、suc_cnt[task] 记录后继个数、successors[] 是一维扁平数组，遍历高效且缓存友好。

③ 位图派发 send_task()

先算「完全空闲」的核（两个 slot 都空：free_bitmap[0] & free_bitmap[1]），再从就绪队列取等量任务，用 __builtin_ctzll 找最低空闲位，逐个绑定核与 slot。

uint64_t free = (free_bitmap[type][0] & free_bitmap[type][1]) & aicore_mask;
int demand = __builtin_popcountll(free);   // 可派发的核数
batch_dequeue(&g_ready_queue[type], ids, &got);  // 取 min(需求, 队列量)
for (each task) {
    idx  = __builtin_ctzll(free);            // 最低空闲核
    slot = (free_bitmap[type][0] & mask) ? 0 : 1;  // 优先 slot 0
    task_id_map[type][idx] = task_id;      // 记录核上任务
    free_bitmap[type][slot] &= ~mask;        // 标记占用
    #ifndef REAL_CHIP
    msg_bitmap[type][slot] |= mask;         // 模拟：立即标记完成
    #endif
}

④ 完成回收 read_msgq / push_2_completed_queue

一轮派发的开头，先把上一轮「已完成」的位图合并回空闲位图（释放核），再扫描完成位图取出 task_id 写入完成队列。

// read_msgq: 完成核被释放
free_bitmap[i][j] |= msg_bitmap[i][j];
// get_completed: 逐位 ctz 取出完成 task_id
while (cnt--) {
    idx = __builtin_ctzll(*bitmap);
    task_id[complete_cnt++] = task_id_map[idx];
    *bitmap &= (*bitmap - 1);   // 清最低位
}

终止条件 termination

0 号 Painter 是唯一累计完成数、判定全图完成的线程：completed_task_cnt >= total_task_cnt 时写 g_is_done = true，所有线程下一轮检查后退出。之所以只让 0 号做，是避免多 painter 并发累加造成竞态或重复判定。

2. DeepSeek V4：pypto ↔ AscendC

一行一个 PyPTO kernel。模块按图上的 mhc、AttentionNorm、mla prolog、o_proj、CSA 来分。AscendC kernel 从 HcPre 起按图上的顺序连续编号到 C4A。一个 pypto 任务盖住连续几个 kernel 时，这几个 kernel 各占一行，pypto 名跨这几行；图上没有单独一行的 pypto 切分并进它所属的 kernel，用同一个编号。按 AscendC 时按模块和编号排。按 PyPTO 时，编号列是流水序号（hc_pre_rms 为 1），AscendC 编号写在 kernel 名前面。图上 7168 的 DynamicMxQuant pypto 没有，qr_proj_matmul 和 kv_proj_matmul 直接吃 BF16，不占号。图里的 HCA、MoE、EP、Embedding、LM head 不在这份 CSA capture 里。

3. SPMD 构建方式

  • 粒度：每个逻辑 dispatch 一节点，外加可选 barrier_dummy；宽度写入 total_spmd_cnt（非 SPMD 为 0）；total_type∈{0..5}（3–5 为 *_SPMD）。
  • 任务数量写法：单任务 a；SPMD a x SPMD(b)（b 为该节点 SPMD 子任务数）。
  • Qwen out / gate / up：每窗收成等宽包——out 5 x SPMD(10)，gate/up 5 x SPMD(17)；HT 多窗直接写成 25 x SPMD(…)；包间无边。
  • 依赖：在逻辑节点上分类边（broadcast / gather / diagonal / bucket / barrier）；包内并行由 spmd_cnt 表达。

6.3 调度需求

这张表看 completion 有多密：调度器在最忙的 5µs 里，要按多快收掉做完的任务。时间从第一个任务下发到最后一个任务完成，按 5µs 切成箱子。C_i 是第 i 箱里的 completion 个数，speed_i = C_i / 5（单位 tasks/µs，数值上等于 MTasks/s）。avg / P90 / P99 / max 对全部箱子计算，空箱也算进去，所以 avg 比忙的时候低。百分位是 nearest-rank：index = ⌈p/100·N⌉−1。加粗的 max 是调度需求，等于最忙那一箱的速率。右边 C_peak 是这一箱的 completion 个数，所以 max = C_peak / 5。

main×5 用 24 个 AIC 的上板泳道：先算上板的 C_i / 5，再乘核数比 120/24=5，外推到 120 核。乘完以后 max 在数值上等于上板原始峰值。例如 CSA LT 最忙一箱是 27 个完成，C_peak 写成 27×5=135，速率是 135/5=27.0。sim120 是 120 核离线模拟，直接分箱，不再乘 5。CSA LT 最忙一箱就是 65 个完成，速率 65/5=13.0。同一场景的两行不是同一次测量；按核数线性放大，也不保证和模拟的峰值形状一样。
